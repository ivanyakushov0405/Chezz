# Линза proportionality — соразмерно ли решение нагрузке, команде и бюджету (F2, F3, F7)
Главный вопрос: **можно ли проще** при цифрах из `docs/setup/BUSINESS.md`? Ошибка, которую ловит эта линза: 14 микросервисов для сотни пользователей онлайн — решение непротиворечивое, соответствует ТЗ и удобно агентам, но сопровождать его некому и не на что.

Возьми из BUSINESS.md нагрузку (пользователи онлайн, запросы в секунду, объём данных, рост), команду (сколько людей сопровождает) и бюджет на эксплуатацию. Значения там — из ТЗ или допущения (помечены). Решение опирается на допущение — 🟠 «зависит от допущения X: если оно неверно, …»; 🔴 — только если для решения нет ни значения из ТЗ, ни допущения.

Для каждого крупного решения документа (число деплоимых единиц, базы и хранилища, брокеры и очереди, кэши, кластеры, отдельные среды, внешние сервисы):
- 🔴 решение рассчитано на нагрузку на порядок выше заявленной на 12 месяцев, без требования из ТЗ;
- 🔴 компонентов, которые нужно сопровождать, больше, чем команда может держать (ориентир: на каждого человека сопровождения — не больше 2–3 отдельно деплоимых компонентов с собственным хранилищем);
- 🔴 стоимость эксплуатации явно не помещается в бюджет;
- 🟠 у решения «по умолчанию» не названа более простая альтернатива и почему она отвергнута;
- 🟠 нет плана «как вырасти»: когда и по какому измеренному признаку переходить к сложному варианту (например, вынос модуля в сервис — при такой-то нагрузке);
- 🟡 инструмент выбран «как у больших», без связи с требованием.

Формат находки — как у всех линз; в «Варианты» обязательно положи более простое решение с оценкой, когда его перестанет хватать.
