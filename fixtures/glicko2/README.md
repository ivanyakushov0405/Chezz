# Эталонные векторы Glicko-2

Форма файлов и прогона — TESTING §7.5; формулы — ARCHITECTURE §11 (A29). Прогон: `apps/server/test/acceptance/glicko2-vectors.test.ts` (проект Vitest `unit`), единственная вызываемая функция — `rateMany` из `apps/server/src/rating/domain/glicko2.ts`. Параметры ТЗ §4.7: τ = 0,5, старт 1500 / 350 / 0,06.

Допуски векторов `generate.py`: rating 0,01, rd 0,01, volatility 1e-6. Значения в файлах округлены до 6 знаков (rating, rd) и 9 (volatility). Volatility строже, чем у примера статьи: за одну партию σ меняется на 1e-6…1e-5, допуск 1e-5 такие ошибки не ловил бы; две реализации Illinois с ε = 1e-6 по x = ln σ² расходятся в σ не больше чем на ~3e-8.

## Независимая реализация (F6-Q2)

- `generate.py` — Python 3 (проверено на 3.14.0), только стандартная библиотека; написана с нуля по статье Glickman, шаги 1–8, итерация волатильности — алгоритм Illinois из статьи, ε = 1e-6. Код не заимствован из других реализаций и не связан с тестируемым кодом `apps/server`. Лицензия — лицензия проекта.
- Запуск из корня: `py fixtures/glicko2/generate.py` — перезаписывает три json. В CI не входит; json вручную не правятся.
- Самопроверка скрипта: пример статьи даёт 1464,0507 / 151,5165 / 0,05999598 — в допусках опубликованных 1464,06 / 151,52 / 0,05999 (запас по rating — 0,0007: статья округляет 1464,0507 вверх).

## Рост RD (F6-Q3, ARCHITECTURE §11)

Перед пересчётом φ′ = √(φ² + c · elapsed_days · σ²) в шкале Glicko-2 (φ = RD / 173,7178), σ — прежняя волатильность, **c = 0,21436** периода в сутки (`lichess-org/lila` `Glicko.periodsPerDay`); RD после роста — не больше **350**. Затем один шаг статьи (шаги 3–8) как период из одной партии, с прибавкой σ′² (шаг 6). При `elapsed_days = 0` роста нет. Скрипт проверяет константу: RD 60 при σ = 0,06 за 365 суток → ≈ 110.
