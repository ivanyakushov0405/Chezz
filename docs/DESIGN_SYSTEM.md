## 1. Правила для агентов

- MUST: стили — CSS Modules (`*.module.css`) рядом с компонентом + CSS-переменные из `apps/web/src/shared/ui/tokens.css` (U1, U2). Другого способа стилизации нет.
- MUST: компонент использует только семантические (`--color-*`, `--space-*`, `--layout-*`, …) и компонентные (`--board-*`, `--clock-*`, `--button-*`, `--judgement-*`) токены. Базовые (`--base-*`) — только внутри `tokens.css` (раздел 3). Все токены разделов 4–6 и 7.1 лежат в `tokens.css`.
- MUST NOT: цвет, отступ, радиус, размер шрифта, ширина литералом в `*.module.css` или `style={}` (`#1f63c6`, `red`, `rgb(…)`, `oklch(…)`, `13px`, `1200px`). Разрешены: `0`, проценты, `fr`, `vw`/`vh`, числа без единиц (`line-height`, `flex`), ключевые слова `transparent`, `currentColor`, `inherit`, `px` только в `@media (min-width: …)`. Толщины и ширины — токены (`--border-width`, `--layout-container-max`, раздел 4). `style={}` — только для своих CSS-переменных: `style={{"--eval-pct": 62}}`. Проверка — раздел 17.
- MUST: корневой элемент экрана несёт `data-screen="<ID экрана>"` и `data-state="<ID состояний через пробел>"` (раздел 10); e2e выбирает состояние селектором `[data-state~="offer"]`.
- MUST: при расхождении F5 с F1, F2, F3, F4 по пунктам списка 18.2 до reopen верен F5 (например, `board_theme` — `brown`, а не `default` из API §4.3).
- MUST: новый токен или компонент `shared/ui` — сначала строка в разделе 4–7 этого документа, потом в код (в той же задаче).
- MUST: каждая строка интерфейса — ключ перевода (раздел 15), ошибка — `error.<code>` (раздел 11). Кодовые значения (`white_wins`) на экран не выводятся (GLOSSARY §12).
- MUST: каждый экран из раздела 9 реализует все свои состояния по матрице 10.4; пустой `catch` и «вечный спиннер» запрещены.
- MUST: ширина от 360 px без горизонтальной прокрутки; на телефоне доска на всю ширину, часы над и под доской (ТЗ §5 «Адаптивность»).
- MUST: клавиатура и контраст AA — по разделу 14.
- MUST NOT: UI-кит (MUI, Chakra, Ant), Tailwind, CSS-in-JS с рантаймом, библиотека графиков, шрифты и иконки с чужих доменов (ARCHITECTURE §14, SECURITY §6 CSP `font-src 'self'`).
- MUST NOT: отдельный пакет дизайн-системы (`packages/ui`) и Storybook — до признака из U3.
- MUST NOT: экраны и компоненты для того, что вне этапа: жалобы, «Пожаловаться», админ-панель, бан, чат, реванш, друзья (BUSINESS §1.7, GLOSSARY §3, G20, G28).

## 3. Токены: уровни и имена

| Уровень | Префикс | Кто использует | Пример |
|---|---|---|---|
| Базовый | `--base-` | только `tokens.css` | `--base-blue-600: #1f63c6` |
| Семантический | `--color-`, `--space-`, `--radius-`, `--font-`, `--shadow-`, `--z-`, `--duration-`, `--border-`, `--focus-`, `--layout-` (размеры раскладки) | все компоненты | `--color-accent: var(--base-blue-600)`, `--layout-touch-target: 44px` |
| Компонентный | `--board-`, `--clock-`, `--judgement-`, `--button-` | один компонент или фича | `--clock-bg-low: var(--color-danger-bg)` |

- Новый размер раскладки — `--layout-<что>`, не `--board-*` / `--clock-*` (те — компонентные цвета).
- Имя семантического цвета: `--color-<роль>[-<вариант>]`, роль — назначение, не цвет: `bg`, `surface`, `border`, `text`, `accent`, `danger`, `success`, `warning`, `caution`. Вариант: `muted`, `hover`, `on` (текст поверх), `bg` (заливка плашки).
- Компонентный токен ссылается на семантический, а не на базовый — тогда он сам меняется с темой. Исключение — цвета клеток доски (раздел 6): они не зависят от темы.
- MUST: темы меняют только семантический уровень (раздел 5).
- Пример: кнопка «Сдаться» — `background: var(--button-danger-bg)`, где `--button-danger-bg: var(--color-danger)`; в тёмной теме меняется только `--color-danger`.

## 12. Разбор: отметки ходов (закрывает GLOSSARY Q3, G23)

Метод Lichess: отметка по падению шанса на выигрыш сходившей стороны.

1. Шанс на выигрыш с точки зрения белых: `wc(cp) = 2 / (1 + exp(−0.00368208 × cp)) − 1`, где `cp` ограничен −1000…1000; результат от −1 до 1.
2. Мат в `n`: `cp = ±(21 − min(10, |n|)) × 100` без ограничения 1000 (знак — в чью пользу мат).
3. Падение `Δ = wc(до хода) − wc(после хода)`, обе оценки — с точки зрения сходившей стороны.
4. `Δ ≥ 0.3` — зевок `blunder` (`??`); `Δ ≥ 0.2` — ошибка `mistake` (`?`); `Δ ≥ 0.1` — неточность `inaccuracy` (`?!`); иначе — без отметки.

| До хода | После | Δ | Отметка |
|---|---|---|---|
| +1.50 | −0.50 | 0.269 − (−0.092) = 0.361 | зевок `??` |
| +0.50 | −0.10 | 0.092 − (−0.018) = 0.110 | неточность `?!` |
| мат в 3 (#3) | +2.00 | 0.997 − 0.352 = 0.645 | зевок `??` |

- Код — чистая функция `judgeMove(before, after, color)` в `apps/web/src/features/games/analysis/judgement.ts` с тестом на строки таблицы.
- Глубина расчёта для отметок — 14 полуходов на позицию (по умолчанию, F5-Q4); оценка текущей позиции углубляется до 20.
- Цвета: `--judgement-*` (раздел 7.1). MUST: рядом с цветом всегда символ (`?!`, `?`, `??`) — цвет не единственный признак (раздел 14).
- `LineChart` оценки строится по `wc` (от −1 до 1), не по сантипешкам — мат не ломает шкалу.

### 16.3. Как сверяются

1. Задача на экран содержит ссылку на фрейм (`…?node-id=…`) или строку «макет: нет».
2. Разработчик берёт состав из раздела 9, вид — из фрейма; значения — только токены. Если во фрейме цвет или отступ вне токенов — берёт ближайший токен и пишет это в PR.
3. PR с изменением экрана прикладывает скриншоты 360 и 1280 px (светлая; тёмная — если менялись цвета) и отмечает в описании состояния своего экрана из 10.4 (чек-лист, раздел 17).
4. Сверка с фреймом — пункт чек-листа ревью PR, не автоматический тест. Сверяет дизайнер-агент или ревьюер (кто — F8): состав (раздел 9) и состояния (10.4) — замечание при расхождении; пиксели — нет.
5. Новый токен из макета — сначала правка разделов 4–6, потом код и переменная Figma.

### 16.4. Если макета нет

Сейчас готовых макетов нет (U34). Файл Figma создаёт дизайнер-агент через коннектор Figma у человека; ссылка на файл — в профиле конвейера (F8).

- Порядок: первая UI-задача — дизайнер-агент создаёт страницы 16.1 и переменные `00 Tokens` из `tokens.css` (U23). Дальше — фреймы экрана в задаче фичи, до или вместе с разработкой, по именам 16.2.
- Экран собирается из компонентов раздела 7 по составу раздела 9 и раскладке раздела 8. Задача не ждёт макета (U24): если фрейма ещё нет — «макет: нет», а дизайнер-агент делает фрейм по скриншотам PR после слияния.
- MUST NOT: дизайнер-агент придумывает в Figma токены, компоненты или состояния, которых нет в разделах 4–10, — сначала правка документа.
- Пример: задача «История партий», «макет: нет» → `history` из `Table`, `Select`, `TextField`, `AsyncState`; на 360 px — карточки; скриншоты в PR.
