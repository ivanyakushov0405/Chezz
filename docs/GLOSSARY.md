## 1. Правила для агентов

- MUST: сущности, поля, значения перечислений и подписи интерфейса брать из этого файла. Синонимы в коде и интерфейсе запрещены (не `Match` вместо `Game`, не `Invite` вместо `Challenge`).
- MUST: новый термин сначала попадает в этот глоссарий (через правку документа и утверждение), потом в код.
- MUST: подписи интерфейса — только через файлы переводов RU/EN (ТЗ §5 «Локализация»); колонки «RU» и «EN» ниже — эталон для ключей переводов.
- MUST NOT: вводить сущности вне беты — турнир, бот, чат, друзья/подписки, вызов по нику, e-mail-уведомления (ТЗ §2, §8; подтверждено человеком, G28). Реванша в ТЗ нет; не вводить его — решение по умолчанию (G20).
- MUST NOT: вводить то, что вне этапа по разделу 3: жалобы, админ-панель, роль администратора, бан, аннулирование партии, журнал действий администраторов, дашборд.
- MUST NOT: считать сущностью то, что здесь помечено как «производное» (таблица лидеров, статистика, лобби, FEN). Категория — не сущность, а хранимое поле `Game.category` и `Rating.category` (ТЗ §6), значение которого вычисляется из контроля времени по формуле раздела 6.
- Где хранится сущность (PostgreSQL, Redis, память) — не здесь, это решает F2. Права и ПДн — F3. Форма API — F4.

## 6. Контроль времени и вызов

| RU | EN | Код | Определение | ТЗ |
|---|---|---|---|---|
| Контроль времени | Time control | `time_base`, `time_increment` | Базовое время + добавка за ход. Показ «3+2» = 3 мин + 2 с | ТЗ §1, §4.5 |
| Пресет | Preset | `TIME_CONTROL_PRESETS` | Готовые контроли: пуля 1+0, 1+1, 2+1; блиц 3+0, 3+2, 5+0, 5+3; рапид 10+0, 10+5, 15+10, 30+0 | ТЗ §4.5 |

| Пуля / Блиц / Рапид | Bullet / Blitz / Rapid | `bullet` / `blitz` / `rapid` | Значения категории | ТЗ §2, §4.5 |
| Рейтинговая | Rated | `rated = true` | Влияет на рейтинг | ТЗ §1 |
| Товарищеская | Casual | `rated = false` | Не влияет на рейтинг | ТЗ §1 |
| Вызов (своя игра) | Challenge | `Challenge` | Партия, которую создаёт игрок со своими параметрами. Поля: `id, creator_id, time_base, time_increment, rated, color, type, rating_range, status, expires_at` | ТЗ §4.3, §6 |
| Открытый вызов | Open challenge | `type = open` | Виден в лобби, принять может любой игрок | ТЗ §4.3 п.2 |
| Вызов по ссылке | Link challenge | `type = link` | Виден только по ссылке | ТЗ §4.3 п.2 |
| Цвет | Color | `color`: `white` / `black` / `random` | Выбор цвета создателем | ТЗ §4.3 п.1 |
| Ограничение по рейтингу | Rating range | `rating_range` | Например ±300; отсчёт от рейтинга создателя в категории вызова (по умолчанию, G19) | ТЗ §4.3 п.3 |
| Лобби | Lobby | производное | Список открытых вызовов | ТЗ §4.3 |

Статусы вызова `Challenge.status` (по умолчанию): `open` → `accepted` (создана Game) | `cancelled` (отменил создатель) | `expired` (30 минут без принятия).

- Внимание: ТЗ §2, §4.2, §4.8 пишут «по каждому контролю (пуля, блиц, рапид)» — там «контроль» означает **категорию**. Rating и таблица лидеров привязаны к `category`, не к `time_base`/`time_increment`.
- MUST: у игрока одновременно не более 1 вызова в статусе `open` и 1 партии в статусе `active` (ТЗ §4.3 п.5).
- Пример: свой контроль 2+12 → 120 + 40 × 12 = 600 с → `rapid`. Контроль 2+1 → 160 с → `bullet`.

## 7. Автоподбор

| RU | EN | Код | Определение | ТЗ |
|---|---|---|---|---|
| Подбор (автоподбор) | Quick pairing | `matchmaking` | Автоматический поиск соперника с близким рейтингом в выбранном контроле; всегда рейтинговый | ТЗ §1, §4.4 |
| Заявка на подбор | Seek | `Seek` | Игрок нажал «Найти игру» и ждёт: игрок, `time_base`, `time_increment`, рейтинг в категории этого контроля, время старта | по умолчанию (G9) |
| Окно поиска | Rating window | — | Начинается с ±100, каждые 5 с шире на 50, максимум ±500 | ТЗ §4.4 п.2 |

- MUST: через 60 с без соперника — предложить создать открытый вызов (ТЗ §4.4 п.3).
- MUST: чередовать цвета игрока; не сводить одну пару более 3 раз подряд (ТЗ §4.4 п.4–5).
- MUST: сводить только две заявки с одинаковыми `time_base` и `time_increment` (G15). Партия получает именно этот контроль.
- MUST NOT: сводить разные контроли одной категории. Пример: заявки 3+0 и 5+3 (обе блиц) в одну партию не сводятся.
- MUST NOT: создавать товарищескую партию через подбор.

Значения (по умолчанию, G6):
- `status`: `active` → `finished` | `aborted`.
- `result`: `white_wins` / `black_wins` / `draw`; у `aborted` — пусто.
- `termination`: `checkmate`, `resignation`, `stalemate`, `threefold_repetition`, `fifty_moves`, `insufficient_material`, `timeout`, `timeout_insufficient_material` (флаг при недостатке материала у соперника — ничья), `draw_agreement`, `abandonment` (истёк таймер переподключения), `no_first_move`, `aborted_by_player`.

- MUST: правила, часы и окончание партии проверяет только сервер (ТЗ §4.6, §5).
- MUST: исход после таймера переподключения фиксируется один раз — по выбору соперника или по истечении окна (G21); только после этого пересчитывается рейтинг. Исходы — только эти три:

| Выбор соперника | `status` | `result` | `termination` | Рейтинг (в рейтинговой партии) |
|---|---|---|---|---|
| Победа (или нет ответа за 30 с) | `finished` | победа соперника | `abandonment` | меняется |
| Ничья | `finished` | `draw` | `abandonment` | меняется как за ничью |
| Отмена | `aborted` | пусто | `abandonment` | не меняется |

- Пример: белые в рейтинговом блице 3+2 не вернулись за 60 с. Чёрные 30 с ничего не выбирают → `finished`, `black_wins`, `abandonment`, рейтинг пересчитан. Если бы чёрные выбрали отмену → `aborted`, `result` пуст, рейтинг обоих прежний.
