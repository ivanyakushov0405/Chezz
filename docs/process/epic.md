Ты ведёшь эпик сам, от брифа до PR, в одном контексте: читаешь, пишешь код и тесты, проверяешь, коммитишь. Субагентов по умолчанию не вызываешь. Артефакты — в `docs/features/<slug>/`: `brief.md`, `log.md`, `review.md`.

Вход: $ARGUMENTS

**Профиль** — `.claude/profile.md`: документы, приложения и модули, проверки, ручные проверки Ivan, выкатка, GitHub, трекер, «Режим работы». Нет профиля — ⛔ «сначала `/setup`».

## Правила
- Документы основ — справочник: читай только нужные разделы (`.claude/kit/scripts/section.sh <файл> <номер>`). Их MUST / MUST NOT действуют. Менять документ основ — только с ⛔ (текст правки целиком) и по решению Ivan.
- Охрана — автоматическая: `npm run check` (tsc, ESLint, Stylelint, границы модулей, сверка API), тесты, CI, хук `guard.sh`. Не обходи их и не выключай правило ради зелёного.
- Тесты пишет тот, кто пишет код, в том же шаге (TESTING §4). Исключение — области слепых тестов (профиль, «Режим работы»): там тесты пишет `tester` до кода.
- Имя теста — точные номера критериев брифа: `it("К-3: …")`; edge case — `"К-3 E-2: …"`.
- Git: ветка `feature/<slug>`; коммит после каждого шага конкретными путями (`git add <пути>`); `git add -A`, `git add .`, `push --force`, мёрж — никогда. Push и PR — только после ⛔.
- Переменная окружения, сервис, внешний сервис, новое хранилище — только через ⛔ (ARCHITECTURE §1, §14).
- Застрял на одной проблеме дольше ~15 минут или трёх попыток — остановись и спроси Ivan одним сообщением, не перебирай варианты.

## 0. Подготовка
1. Slug: `e<N>-<кратко>` для эпика, иначе `<кратко>`.
2. Проверки, при провале — ⛔: зависимости эпика выполнены (ROADMAP); `infra-up` проходит.
3. `git switch main && git pull --ff-only && git switch -c feature/<slug>`. `log.md`: дата, время старта.
4. Трекер `jira`: эпик → in_progress (одна смена статуса; задач в Jira не заводить).

## 1. Бриф
Прочитай строку эпика и «Пояснения к нарезке» в ROADMAP, нужные разделы ТЗ и документов основ, текущий код затронутых модулей. Напиши `docs/features/<slug>/brief.md` по шаблону `docs/process/brief-template.md` — не больше страницы.
⛔ **Утверждение брифа**: путь, критерии К-1…К-n, шаги, `Риск:` эпика, правки документов основ (текст целиком), вопросы. Без «да» — не начинай.
После «да»: правки документов основ → внеси → коммит `docs(<документ>): <что> [<slug>]`; `brief.md` → коммит `docs(<slug>): brief`.

## 2. Шаги — по порядку брифа
Для каждого шага:
1. Область слепых тестов (профиль) → `tester`, режим 1, по брифу и публичным интерфейсам шага → коммит `test(<scope>): … [<slug> шаг N]`. Иначе — пропусти.
2. Код и свои тесты (unit, int, contract — по уровням TESTING §5).
3. `npm run check` и `git fetch origin main && npm run test:affected` — зелёные. Красные — чини.
4. Коммит `feat(<scope>): <что> [<slug> шаг N]`.
5. Одна строка в `log.md`: шаг, что сделано, время.
Шаг вышел больше ~8 файлов или нужен другой план — допиши шаги в `brief.md` (новые или разбитые), строкой в `log.md`; меняются критерии или документы основ — ⛔.

## 3. Ревью — одно на эпик
`reviewer`, режим «эпик»: путь к брифу, `git diff main...HEAD`, затронутые зоны (по путям). Модель: `Риск: high` эпика → opus, иначе sonnet.
Блокеры чини сам → коммит `fix(<scope>): review [<slug>]` → повторное ревью только по блокерам (тот же агент, `SendMessage`). Больше двух итераций — ⛔.
«Желательно» — делай, если дёшево, остальное — в раздел «Позже» PR.

## 4. Приёмка
1. `npm run test:e2e -- <сценарии эпика>` и `@smoke`. Firefox локально может не запускаться (окружение) — проверяет CI.
2. «Ручные проверки Ivan» профиля — что из них нужно этому эпику.
3. `log.md`: время окончания, токены сессии (`/explain-usage` или оценка), сколько настоящих ошибок нашло ревью.
4. Сводка человеку: критерии с отметкой, правки документов основ, новые переменные окружения (только имена), «Позже», чек-лист демонстрации по критериям.

## 5. PR
⛔ **Разрешение на push** (diff `.github/`, `deploy/`, `scripts/ops/` — показать до push, O36; `.github/workflows/**` пушит Ivan). После «да»: `git push -u origin feature/<slug>`, `gh pr create` со сводкой, чек-листом и «Позже». Трекер `jira`: эпик → done после мёржа. Мёрж — Ivan; выкатка — `/release`.
