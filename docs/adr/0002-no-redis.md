# ADR-0002. Без Redis на этапе беты

Статус: предложено. Дата: 2026-11-04.

## Контекст
ТЗ §6 рекомендует Redis для очереди подбора, онлайн-статусов, часов, pub/sub и кэша лидеров. Бэкенд — один процесс `app` (ARCHITECTURE.md A1); пик — 150 онлайн, 75 партий, ≤ 100 сообщений/с (ТЗ §1, BUSINESS.md D2); один VPS и один сопровождающий (D4, D6).

## Решение
Redis не используем. Seek, онлайн-статусы, pub/sub (`events` модулей внутри процесса, ARCHITECTURE.md раздел 7.3) и кэш лидеров — в памяти `app`; надёжное состояние партии и часов — в PostgreSQL после каждого хода (ТЗ §5). Разбор по задачам — ARCHITECTURE.md раздел 6.2.

## Последствия
- Минус один контейнер в каждой среде, его память, обновления и мониторинг.
- Seek теряются при перезапуске — клиент отправляет заявку заново.
- Redis вводится вместе со вторым процессом `app` по измеренному признаку (ARCHITECTURE.md раздел 15).
