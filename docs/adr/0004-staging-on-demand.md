# ADR-0004. staging по требованию

Статус: предложено. Дата: 2026-11-04 (ревью F2 r1, prop-3).

## Контекст
ТЗ §6 требует prod и staging; BUSINESS.md D9 — выкатка после проверки на staging. Один VPS и один сопровождающий (D4, D6). staging нужен на время smoke перед выкаткой и для нагрузочного теста этапа 5 (ТЗ §7).

## Решение
staging поднимается CI-workflow (compose-профиль `staging`) с одноразовой БД: миграции + сид. После smoke (и, если нужно, нагрузочного теста) среда гасится. Бэкап staging не делается. Закрытое тестирование этапа 5 (10–20 человек) идёт на prod. Подробности workflow — F7.

## Последствия
- Постоянно на VPS работают только `edge`, `app` и `db` prod.
- Долгоживущих данных на staging нет. Если они понадобятся — постоянный staging с бэкапом (ARCHITECTURE.md раздел 15).
