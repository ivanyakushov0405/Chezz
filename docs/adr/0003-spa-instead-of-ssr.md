# ADR-0003. SPA + серверный HTML публичных страниц для SEO, без Next.js SSR

Статус: принято. SEO нужен — решение человека (Ivan, утверждение F2, 2026-11-04, F2-Q4); способ выбран по умолчанию. Дата: 2026-11-04.

## Контекст
ТЗ §6 рекомендует React / Next.js с SSR для публичных страниц. Человек подтвердил: страницы профиля, таблицы лидеров и завершённой партии должны индексироваться. Ограничения: один небольшой VPS и один сопровождающий (BUSINESS D4, D6), бэкенд — один процесс `app` на Fastify (ARCHITECTURE.md A1, A2). По ТЗ §5 первая отрисовка — ≤ 2,5 с на 4G, главная — ≤ 300 КБ gzip.

## Варианты
| Вариант | Индексируемый HTML | Лишний процесс | Сложность |
|---|---|---|---|
| Только мета-теги в `index.html` | Нет: без JS тело страницы пустое | Нет | Минимальная |
| **Шаблоны HTML в Fastify (модуль `seo`) + SPA** | Да: мета-теги и простая разметка данных | Нет | Низкая: шаблоны на три маршрута |
| Пререндер при сборке | Устаревает после каждой партии | Нет | Средняя: пересборка по данным |
| React SSR с гидрацией в Fastify | Да, полный интерфейс | Нет | Высокая: Vite SSR, код, безопасный для сервера, расхождения гидрации |
| Next.js | Да | Да, в каждой среде | Высокая |

## Решение
SPA на Vite. Для публичных маршрутов модуль `seo` в `app` подставляет в `index.html` мета-теги и простую семантическую разметку данных из шаблонов (без React на сервере). React монтируется через `createRoot` и заменяет разметку. Также генерируются `sitemap.xml` и `robots.txt`. Подробности — ARCHITECTURE.md раздел 12.1.

## Последствия
- Процессов не добавилось; клиент и сервер выкатываются одной версией.
- Данные публичных страниц выводятся дважды: в шаблонах `seo` (простой вид) и в SPA. Шаблоны держим минимальными.
- Шаблоны выводят данные пользователя: обязательно экранирование (F3).
- Переход к React SSR — по признаку из ARCHITECTURE.md раздела 15.
