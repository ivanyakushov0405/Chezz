# F5 — agentability, раунд 1

Размеры: все разделы уровня 2/3 ≤ ≈1050 ток. (§2 и §9 делятся на подразделы ≤ 979). Бюджет соблюдён.

## 🔴 agentability-1. Нет матрицы «экран × обязательные состояния», и правило непроверяемо
§1 («каждый экран из раздела 9 реализует все свои состояния из раздела 10») и §10 (таблицы 10.1–10.3) не связаны. Не сказано, какие состояния есть у `settings`, `welcome`, `profile`, `game-review`, `analysis`, `challenge-new`. Например, нужны ли у `analysis` «загрузка / ошибка движка» (в §9.4 только прогресс), у `profile` «не найдено», у `leaderboard` «ошибка». §17 не содержит строки про покрытие состояний: ни теста, ни пункта чек-листа ревью. Последствие: дизайнер-агент рисует свой набор состояний, разработчик реализует другой; шаг 4 в §16.3 («расхождение в составе или состояниях — замечание») не с чем сверять. Варианты: (а) добавить в §9 колонку «Состояния» с перечнем из §10 по каждому ID; (б) в §10 добавить колонку «Экраны»; и в обоих случаях строку в §17 (пункт чек-листа ревью PR или тест, что для `AsyncState` заданы все 4 ветки).

## 🟠 agentability-2. У состояний и экранов нет ID, «буква в букву» из §16.2 невыполнимо
§16.2 требует, чтобы имена фрейма `game-live / 360 / dark / reconnect` совпадали с документом буква в букву. Но §10 называет состояния русскими фразами («Переподключение», «Окно выбора»), ID `reconnect` нигде не определён. Экран «`game-live` зритель» (§9.3) — ID с пробелом, а пробел и `/` в имени фрейма служат разделителями. Для диалогов `challenge-new`, `feedback` и `account-delete` не сказано, это фрейм экрана или компонента. В Figma-варианте `state=default` у `Button` не перечислены допустимые state. Последствие: два агента назовут по-разному, сверка скриншотов с фреймом ломается. Варианты: (а) добавить в таблицы §10 колонку ID (`loading`, `empty`, `error`, `not_found`, `reconnecting`, `offline`, `first-move`, …); (б) дать зрителю ID `game-spectator`; (в) в §7 перечислить state компонентов (`default`, `hover`, `focus`, `disabled`, `loading`).

## 🟠 agentability-3. Компонентные и часть семантических токенов нигде не определены
§3 допускает компонентам `--button-*`, `--clock-*`, `--judgement-*`, а §1 требует «сначала строка в разделах 4–7». Но значений нет: `--button-danger-bg`, `--clock-bg-active`, `--clock-bg-low`, `--judgement-*` встречаются только в примерах (§3, §9.3, §12). Семантических `--color-danger-bg` (§3), `--shadow-m` (§5, §3), `--color-success-bg` нет в §5. Не сказано, лежат ли `--board-*` из §6 в `tokens.css`. Последствие: разработчик придумывает значения, чем нарушает собственное правило MUST; дизайнеру нечего вести в Figma `00 Tokens`. Варианты: (а) таблица компонентных токенов в §7 или §5 (токен → ссылка на семантический); (б) дописать в §5 `--shadow-*` и `-bg`-варианты; (в) одной строкой: `--board-*` лежат в `tokens.css`.

## 🟠 agentability-4. Stylelint-правило из §17 не может быть реализовано по тексту
Строка «запрет `px`/`rem` кроме разрешённых (раздел 1)»: в §1 исключения `0`, `100%`, `1px у границ`. Но `@media (min-width: 768px)` (§8), `max-width: 1200px`, `640px`, `44px` (§8) — это литералы по тому же правилу. `color-no-hex` не ловит `rgb()/hsl()` и именованные цвета (`red`). Литералы в `style={}` (§1 MUST NOT) не проверяются ничем. Конфиг и место правила (`.stylelintrc`) не названы. Последствие: правило либо даёт ложные срабатывания на §8, либо пропускает нарушения; агент «чинит» линтер. Варианты: (а) перечислить допустимые: `unit-allowed-list` и исключения для `@media`, размеров контейнера (в `tokens.css` завести `--container-max`, `--board-max`, `--touch-target`); (б) добавить `color-named: never`, `function-disallowed-list: [rgb, rgba, hsl, hsla]` вне `tokens.css`; (в) для `style={}` — правило ESLint `react/forbid-dom-props` или grep в `check-architecture.sh`.

## 🟠 agentability-5. Контраст и скриншоты: проверка описана, но не воспроизводима
§17 «тест: таблица пар „текст / фон“ обеих тем» — таблица пар не дана и не сказано, где она лежит; пары `--color-warning`, `--color-success`, `--color-danger` на `--color-surface`, текст `--color-accent-on` на accent, `--board-*`/`--clock-bg-low` не перечислены. Проверка 360 px — «e2e-скриншот (форму — F6)», при этом скриншоты в PR (§16.3 п.3) делает человек/агент, а сверка (п.4) — «если он есть». Никакой автоматической проверки соответствия фрейму нет. Последствие: «контраст AA» остаётся словами. Варианты: (а) вынести список пар в `tokens.contrast.json`-подобный источник (или в §5 колонкой «проверяется с …»); (б) явно записать, что сверка с Figma — пункт чек-листа ревью PR (а не тест), и привязать к F6/F8.

## 🟡 agentability-6. Нет маршрута чтения по ролям
§1 — общие правила; сказано «открой нужный раздел», но не какие. Для дизайнера-агента (§3–6, 8–10, 16) и разработчика (§1, 3, 5–7, 9–11, 17) стоит дать две строки «Читай» в начале; иначе агент прочтёт ≈17,8k токенов целиком. Вариант: две строки в «Как читать».

## 🟡 agentability-7. Узкие места API компонентов и ширин
§7: только `Button` и `IconButton` имеют названные props; у `Dialog`, `Table`, `Tabs`, `Select`, `AsyncState` нет списка props (`AsyncState`: как передать состояние запроса?). Вариант: добавить колонку «Props» или сослаться на типы в коде. §16.2 требует кадры 360 и 1280, а раскладка `m` (768–1023, §8) не имеет эталонной ширины — вариант: добавить `768` для `game-live`.

## 🟡 agentability-8. §18.2 отправляет агентов в противоречие с утверждёнными документами
«До reopen агенты следуют F5» — но F4 §4.3 всё ещё говорит `default` для `board_theme`/`piece_set`, а F2 §4.2 — «библиотеку выбирает F5». Агент, читающий F4/F2 разделами, увидит старое. Вариант: добавить в §1 один MUST «при расхождении с F2/F4 в перечисленных пунктах §18.2 — приоритет у F5».
