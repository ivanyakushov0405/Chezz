## 🟠 consistency-r2-1. Шаг tester «готов»: п.2 и п.3 несовместимы
§4, «Шаг tester готов»: п.2 требует, чтобы файлы тестов проходили `npm run check` (`tsc -b`, импорт только из «Публичных интерфейсов» `design.md`); п.3 допускает красный тест, потому что «функции ещё нет». До кода функции, модуля или маршрута нет, поэтому `tsc -b` падает с «модуль или экспорт не найден» — п.2 невыполним ровно в тех случаях, о которых говорит п.3 (acceptance, unit-векторы Glicko-2, contract через типы `packages/protocol` — те уже есть).
Последствие: tester не может закрыть шаг по DoD; агент либо создаёт заглушки в `src/` (запрещено §4), либо нарушает п.2.
Варианты: (а) п.2 — «`eslint` проходит; `tsc` допускает только ошибки отсутствия модуля или экспорта из `design.md`»; (б) задача скелета/architect создаёт типизированные заглушки публичных интерфейсов по `design.md` до шага tester; (в) тесты tester вне `tsc -b` (отдельный `tsconfig` с `noEmit` только для проверки после реализации).

## 🟠 consistency-r2-2. Вид C: ожидаемые значения не заданы, пропуск разрешён только для B
§7.5, таблица: вид C (`elapsed_days > 0`) вызывается «функцией одного результата; константа — F6-Q3». F2 §11 константу роста RD не задаёт, F6-Q3 открыт. Значит, ожидаемое RD для вида C взять неоткуда, но `it.skipIf` по §1 и §11 разрешён только для B. Тест C либо не пишется, либо красный без причины в коде. Чуть раньше §7.5 говорит «вид B — до reopen F2 пропуск», про C — ничего. Набор (3) (≥30 партий, независимая реализация) тоже не отнесён ни к одному виду; если в нём есть `elapsed_days > 0`, это C.
Последствие: acceptance «рейтинг по Glicko-2» (ТЗ §7) не закрывается без решения F6-Q3; tester застревает на шаге 1 фичи `rating`.
Варианты: (а) распространить `skipIf` и признак `"kind"` на C («ожидание не задано до F6-Q3»); (б) закрыть F6-Q3 по умолчанию сейчас (константа Lichess, значение записать в 7.5); (в) в 7.5 прямо сказать, что набор (3) состоит из видов A и B.
