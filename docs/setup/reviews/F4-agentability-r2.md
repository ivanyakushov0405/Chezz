## 🟠 agentability-10. §15 и §16 опираются на несуществующие артефакты без владельца
Инструменты `registerRoute`, `api.call`, `wsHandlers`, `scripts/check-api-doc.sh`, `npm run -w packages/protocol dump`, `onRoute`-тест, `snapshot/protocol.json` в репозитории появятся только после написания; ни одна строка не говорит, чья это задача и в какой момент. F2-Q12 (сборка `api.ts`) остаётся открытым, а §15 уже предписывает `registerRoute` из `platform`. Последствие: первый агент, добавляющий маршрут, не найдёт инструментов и выдумает их по-своему; шаги 4 и 5 невыполнимы до скелета. Варианты: (а) строка в §15/§16 «создаются задачей скелета репозитория (F2-Q12), до неё шаги 4–5 выполняются вручную по описанию» с сигнатурами `registerRoute`/`wsHandlers`; (б) вынести в 17.1 вопрос с владельцем «задача скелета: platform.registerRoute, dump, check-api-doc».

## 🟡 agentability-11. Часть MUST из §1 без проверки в §16
Нет проверки для «время с клиента не принимается» и «`ply` только у перечисленных команд» (покрыто строгостью схем неявно), «ответ на `ping` из обработчика», «POST/PATCH с `Origin`» (частично через `registerRoute`).
