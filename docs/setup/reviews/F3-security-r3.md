# F3 — security, раунд 3

## Прошлый раунд
- 🔴 sec-13 закрыта (§4.1, S31). Каждый изменяющий шаг — `POST` с `Origin` и Session. Цель `delete` попадает в `__Host-oidc` только через POST, а GET начала входа её игнорирует (§4). На возврате от Google ничего не удаляется. Google спрашивает явно (`prompt=select_account`). Удаление выполняется отдельным `POST` с `__Host-del` (`SameSite=Strict`, привязана к `id` Session, 5 мин). Против кликджекинга страницы подтверждения — `frame-ancestors 'none'` (§6). Атака ссылкой или `<img>` больше не работает. С украденной cookie без входа в Google жертвы шаг 2 не пройти.
- 🟠 sec-14 закрыта (§4, S30): отказ, если `u.pathname` начинается с `//`, редирект на абсолютный `u.href`, а `/.//evil.example` и `https://evil.example` внесены в обязательный unit-тест. Варианты с `%2F` после разбора остаются путём своего origin.
- 🟡 sec-15 закрыта: свежесть даёт `started_at` по часам `app`, `auth_time` проверяется, только если Google его прислал.
- 🟡 sec-16 закрыта: обёртка `scripts/ops/ro.sh` с `PGOPTIONS`.
- 🟡 sec-17 закрыта как принятый риск с ограничениями (§17): секреты staging ничего не дают для prod, `deploy/**` берётся из `main`, сборка идёт без секретов.
- 🟡 sec-18 закрыта: upgrade входит в лимит REST 300/мин (§9).
